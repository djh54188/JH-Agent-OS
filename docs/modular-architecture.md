# JH-Agent OS 模块化架构

日期：2026-10-17。状态：已确认的模块方向，接口细节与实现技术待设计和实测；不是已实现架构。
依据：[产品需求 v1.1](product-requirements-v1.1.md)、[ADR-0005](adr/ADR-0005-modular-gui-agent-hub.md)。

## 1. 六个模块及状态归属

| 模块 | 职责与接口 | 不承担的职责 |
|---|---|---|
| GUI | 页面、公共组件、数据访问；提交操作意图并展示查询/事件 | 直接读写业务数据库、调用 Agent 工具或决定成功 |
| 应用接口 | GUI/CLI 统一入口，输入校验、身份与授权上下文、业务命令和查询 | 复制一套任务状态机或在页面专用路由中放宽规则 |
| 协作核心 | 任务生命周期、会话登记、消息路由、流程版本、依赖、额度内重试与升级 | 特定应用的协议细节、任意工具执行或自行批准操作 |
| Agent 适配器 | 探测应用能力；派发、进度、接续、取消、收集；将原生事件映射为公共事件 | 自报即可信、改变任务成功条件或绕过宿主权限 |
| 审查与控制 | 可信验收、当前产物审核绑定、权限、预算、所有权与不确定性门 | 依赖 GUI 隐藏按钮作为权限保障 |
| 存储与证据 | 提供仓储/事务接口，持久化任务、会话、消息、证据、项目与经验 | 对外部自报内容自动授予可信来源身份 |

任务事实由协作核心经存储接口维护；审查与控制给出可复查的裁决依据。适配器只拥有原生会话句柄和连接事实，GUI 只拥有展示状态。

## 2. 依赖与部署

```text
GUI / CLI / 未来其他入口
            ↓
        应用接口
            ↓
        协作核心 ── 审查与控制
            ↓             ↓
  Agent 适配器接口     存储与证据接口
            ↓             ↓
     外部 Agent       现有 SQLite 等实现
```

核心依赖接口，不导入前端或具体应用实现；应用装配层注入适配器与仓储。首版采用同一工程内的模块化结构，不要求微服务、独立消息中间件或重新建设 Agent Runtime。

## 3. GUI 内部模块化

- 页面模块：工作台、Agent/会话、任务/项目、协作流程、审查/交付、经验/设置。
- 公共组件：任务卡片、状态标记、连接提示、证据查看、审批面板、错误与加载状态。
- 数据访问层：统一应用接口客户端、查询缓存、事件订阅和断线后重查。
- 页面只读服务端任务事实，不用乐观 UI 把任务标成功；审批由后端按实际动作再校验。
- GUI 可使用模拟数据独立开发；模拟服务必须显式标记，不计真实接入或验收。
- 未来网页/桌面入口共享业务接口，换布局或框架不改变核心。主题、布局和组件接口先保持简单，暂不建设插件市场或动态执行第三方界面代码。

## 4. Agent、会话、模型与角色

登记模型：应用类型/实例 → 原生会话标识 → 模型配置 → 当前角色。角色与模型名称不充当唯一会话地址。
同应用不同会话、跨应用会话均可参与同一流程；ZCode 是首个候选，接口尚未验证。应用切换更新适配器和会话映射，不要求改变核心任务协议。
审查会话须独立于执行参与者；不同会话名称本身不证明独立，需核对实际职责、输入和审查证据。

以下为接口设计项，不是现有生产方法或新增 Schema：

| 操作 | 必须说明的事实 |
|---|---|
| capabilities | 支持哪些动作、工作区/会话绑定、观测与取消限制 |
| submit | 幂等派发标识、会话选择、允许范围、返回原生运行标识 |
| status | 排队/接受/运行/完成/失败/未知，及实际可观察依据 |
| collect | 本轮产物、提交/哈希、原始记录引用、用量及未验证事项 |
| continue | 向指定会话发送本轮整改，不重置任务预算或授权 |
| cancel | 区分请求已发出、原生端确认取消和副作用尚未知 |

应用可通过受支持 CLI/API/MCP 等实现；不要求所有应用具备全部能力。不支持自动启动的应用降级为通知或人工接续，UI 明示限制；不把文件落盘等同于模型被唤醒。
ModelAdapter 保留模型 API 的请求/响应职责；AgentSessionAdapter 负责已有 Agent 的执行生命周期，两者可共存但不得互相冒充。

## 5. 消息与流程

采用结构化信封和可读正文：message_id、task_id、attempt/轮次、来源/目标会话、事件类型、流程版本、工作区、基线/交付提交、产物版本哈希、证据引用和关联消息。
以上是设计字段，新增协议需独立版本与兼容计划；不直接要求现有 Task/ReviewResult Schema 接受新字段。
下一对象来自已授权流程的角色到会话映射，发送方不可通过正文或自报 next_agent 改写它。
通知/投递生命周期独立于任务状态；不能把 sent、delivered、reported_complete 或 current=true 映射成 succeeded。
重复事件去重、旧轮次拒绝、有限修复、取消与迟到消息处理必须可验证。持久化消息和相应任务改变应事务一致；不声称外部执行天然 exactly-once，不盲目重放不确定副作用。

## 6. 自动审查触发

活跃任务内的结果接续与结束后的会话唤起是两种能力，分别探测。实际审查对象固定到提交/产物，审查启动和结束都有可关联记录。
Codex 宿主接续方式、目标线程绑定和权限须本机验证；不默认能控制当前桌面聊天，不默认另建线程代替当前架构师。未授权新会话不自动创建。
GUI 的流程编辑不会自动批准工具权限。未知用量、预算超限、执行结果不明或来源不可信沿用既有停止/升级机制。

## 7. 复用与验收

| 现有成果 | 目标模块中的处置 |
|---|---|
| 任务/审核绑定、预算、状态机、恢复约束 | 审查与控制及协作核心，保留硬门禁 |
| SQLite、产物、事件、经验基础 | 存储与证据，先复用，不新增消息中间件 |
| Provider 模型适配器 | 保留 API 通道，独立于外部 Agent 适配器 |
| Skill/CLI、host-entry 与 capture binding | 保留既有能力与证据范围，不冒充通用外部应用支持 |
| FileToolExecutor / production complete | 继续关闭；外部 Agent 也不能借 GUI 绕过准入 |

模块边界验收：用两个 GUI 数据客户端或模拟入口调用同一应用接口；替换模拟 Agent 适配器不改核心；调整流程不改权限策略；各模块独立运行有意义的正反控。
真正产品验收还须一个外部 Agent 在隔离任务真实执行、交付自动触发指定独立审查、一次退回整改、GUI 可见结果；模拟测试不替代真实演示。
代码/数据代表任务和全部原控制要求保留，具体新版验收细则待单独实施。本次仅文档对齐，不派发任务。
