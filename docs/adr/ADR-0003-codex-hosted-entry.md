## 问题与决策

用户在 Codex 内提出目标。Codex 主控通过项目级 Skill 调用结构化 `python -m src.cli`，JH 负责已批准模型之间的协作、独立审核绑定、可信验收、调用预算及任务证据，结果返回当前 Codex 会话。

采用 `.agents/skills/<项目技能名>/SKILL.md` 作为项目流程说明；它不授予权限。实际硬约束位于 JH 控制层、受控应用机制及宿主自身沙箱/审批，各自负责其执行范围。

取消旧 E4 自研通用 Shell/Git 平台的计划。Codex 承担日常代码浏览、Shell、测试与 Git。保留 FileToolExecutor 的最小暂存、审核绑定及受控应用职责，但当前版本的五项缺陷须整改；不把组件保留等同于验收通过。

## 入口职责与限制

- 可信本地装配决定工作区、角色配置、工具模式、支持的任务类型和验收器；模型和任务载荷不得更改权限或自行选择 Mock 生产通道。
- 真实模式缺凭据/配置、预算不足或用量不确定时如实停止；测试模式显式标记，不冒充真实闭环。
- 发起、只读查询、继续已有任务与取消采用有界 CLI 操作。延续持久化预算、截止时间、审核和所有权；不要求 N1 建队列或常驻调度器。
- 查询不建库、不迁移、不调用模型。结构化结果明确区分命令成功与任务结果，包含当前产物与审核、验收、预算和阻塞。
- Skill 不自动执行 approve，不把模型角色声明视为人工授权；recover 不能作为普通 resume 或抢占活跃任务的手段。
- 任务成功仍要求当前独立审核 pass、全部必需验收通过、无未解决权限/预算/副作用不确定性；实际应用字节须与当前审核绑定一致。
- N1 使用已有可信验收器支持的一个代表任务证明宿主内接入；完整产品 P1 与任意开发任务验收仍在 N2。

## 推进顺序与完成条件

JH-015 修复与独立复核仍先于该组件真实文件写入接入；当前组件设计已暂停。按 ADR-0004，JH-004 直接实施真实无工具生成闭环、Skill、只读查询/摘要及跨进程接续，产物使用已有内部持久化。不能证明安全的目标写入保持关闭，不允许拿真实用户文件探测。

完成条件：实际 Codex 项目会话能发现并调用技能，发起任务、跨 CLI 进程查看及接续、接收结果与证据；异常/需授权分支如实返回，预算与审核等门禁不被新入口绕过。单纯新增 Skill 文件、直接注入 Python Orchestrator 或历史正常闭环报告均不足以证明完成。

## 未采用方案与代价

暂不引入独立 MCP 入口，原因是当前 CLI 可以复用且需先验证产品收益。MCP 可以使用 stdio 子进程，不能笼统称为必需常驻 daemon；后续若 CLI 不足以表达所需工具接口，再评估 MCP。

本方案需要补齐可信 CLI 装配和只读路径，并修复受控应用缺陷；已有旧 E1—E3 模块按功能复用，不要求所有历史组件进入默认生产路径。
