- 状态：范围裁决生效；JH-004/N1 已按本范围验收（2026-10-14），N2/P1 未完成
- 日期：2026-10-13（Asia/Shanghai）
- 决策者：当前架构师兼独立审查会话；依据用户要求在发布矩阵失败时直接裁决范围
- 关联：ADR-0003、JH-002 / JH-004 / JH-015 / JH-016、N1 / N2
- 证据：[父目录发布矩阵复核](../../reports/jh016-parent-publish-review-20261013.md)
- 替代范围：此前交接中“JH-015 先完成，JH-004 仅做草案/只读准备”的当前排期；不替代原文件安全契约，不改变 N2 完整 MVP 验收

2026-10-14 验收补记：真实宿主与双模型证据齐备，[裁决](../../reports/n1-acceptance-20261014.md)批准 N1；自动应用仍未通过，不修改本 ADR 边界。

## 原因

父目录 SHARE_READ 发布方案的先行矩阵为 STOP：自身 rename/replace 失败，另一个进程创建子文件仍成功。继续局部加检查不能使该已证伪的前提成立。产品要求优先复用 Codex 的文件与工具能力，当前最重要的缺口是实际宿主内接入，而不是扩建文件发布平台。

## 决策与执行边界

1. 停止本轮自动发布设计的后续整改排期。保存未提交实现、失败证据与原测试，JH-015 维持未通过、暂缓准入；JH-016 本轮复核结论 STOP。FileToolExecutor 的候选最小职责可保留，不进入本批默认生产装配，真实写入门禁关闭。
2. JH-004 当前交付是 Codex 主控 → 项目 Skill → 结构化 CLI → 真实 Gemini 生成 → 真实 Muse 独立审核 → JH 验收与有界修复 → 返回产物和证据。使用已有 SQLite/ArtifactStore 保存产物，允许可信内部持久化；不应用到用户目标文件。
3. 生产生成路径使用显式无工具执行器，拒绝全部模型工具请求，不能使用 MockToolExecutor 回包冒充执行。生产/fixture 来源、任务类型及可信验收配置固定并持久化，后续 resume 不得串换。
4. N1 仅支持一个固定、可由控制层独立计算期望结果的数据整理模板。拒绝未知模式、任意验收名或伪造 expected_output 放行。沿用当前验收器双条件限制时，两项必需条件明确固定，不静默接受更多条件。
5. 发起、只读查询、跨 CLI 进程接续及结果返回均须实际验证。接续继承原预算、截止时间、绑定与所有权；未知副作用和未确认调用不自动重放。Skill 不自动 approve，也不用 recover 作为普通 resume。
6. 结构化结果区分命令完成与任务成功。succeeded 仍须当前有效独立审核 pass、所有必需验收通过、无权限/预算/用量/副作用不确定性；摘要明确 generated_artifact 交付范围和未应用文件的事实。
7. 实际项目级 Skill 发现/调用必须在 Codex 宿主验证。文件存在、CLI 单测、Python 注入及旧真实模型报告都不能替代宿主证据。若旧 C 盘会话绑定妨碍 D 盘项目技能发现，保持未验证并准确说明外部条件。
8. 八阶段不变，N1 不因本 ADR 自动结项。N2 仍须真实代码修改与数据任务、宿主应用及测试、修复与异常分支等完整证据。暂缓组件不等于取消这些产品要求。

## 未批准事项与后续代价

不接受 W1 的覆盖后 uncertain 作为防覆盖保证；不批准自动扩大权限、TxF/独占卷研究、通用 Shell/Git 平台或新的常驻运行层。

本批成功只能证明生成产物协作入口。N2 需要另行确定宿主应用交接与版本检查机制，并核实其实际保障；不能将文件写入请求悄悄改为生成文本后宣称已完成。重新启用 FileToolExecutor 时，原失败案例与契约继续约束准入。
