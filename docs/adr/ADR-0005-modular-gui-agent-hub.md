# ADR-0005：模块化 GUI 与可替换 Agent 协作中间站

- 日期：2026-10-17（Asia/Shanghai）。状态：用户已批准方向，尚未实现或验收。
- 决策依据：用户提出跨 Agent/同应用不同会话的消息中间站，指定其作为统一 GUI，并确认系统与 GUI 均模块化；本次要求更新全部方向文档。
- 当前动作：仅文档对齐，暂不向执行 AI 派发实施任务。
- 需求：[v1.1](../product-requirements-v1.1.md)。设计：[模块化架构](../modular-architecture.md)。排期：[路线 v3.0](../../ROADMAP.md)。

## 决策

1. JH 统一 GUI 成为目标产品的主要用户入口；Codex 保留默认主控、架构与独立审查职责，已验收 Skill/CLI 继续兼容。
2. 中间站登记应用实例、会话、模型与角色，协调预设的下一步；模型仍在各自 Agent 环境运行。支持跨应用与同应用不同会话，不固定 ZCode、Muse、Gemini 或其他供应商。
3. 六模块为 GUI、应用接口、协作核心、Agent 适配器、审查与控制、存储与证据。GUI 内再分页面、公共组件、数据访问层；业务规则不进入页面。
4. 稳定契约和依赖注入支持替换；首版模块化单体，不预先拆微服务、不重建通用 Agent Runtime/Shell/Git。
5. 既有 ModelAdapter 作为模型 API 通道保留，外部 AgentSessionAdapter 单独设计；普通 API 调用不证明完整 Agent 能力。
6. 交付自动触发指定独立审查，退回则有界整改。消息已投递、目标实际开始工作、审核通过、任务成功分开判断。
7. 自动启动/接续目标会话须接口实测；未验证时标为不支持或人工接续，不默认唤醒当前 Codex 桌面会话，不隐式更换架构师。

## 被替代与保留的范围

- 替代需求 v1.0 和路线 v2.0 中“Codex 是主要用户入口”“独立 GUI 暂缓/不建设”的目标约束，以及将固定模型分工当作未来唯一架构的表达。
- ADR-0003 的 Skill/CLI 变为已验收兼容入口；ADR-0004 的历史 N1 范围和自动文件应用 STOP 不变。ADR-0001/0002 的历史设计/已批准接入配置不因此被自动改写。
- N1 按原范围已结项，旧 E 阶段结论保留；新增 GUI 和通用 Agent 协作不算已完成。N2/P1 门槛增加新产品闭环，不删除原代码/数据代表任务。
- 成功必须仍有当前有效独立审核、全部必需验收与可信证据，且无权限、预算、未知用量或副作用不确定性。production complete、FileToolExecutor 继续关闭。
- 外部 Agent 并非 Codex，不要求其伪装 Codex 日志；其原生来源证据需另定契约并独立验证。现有 Codex-only capture binding 不能直接泛化为所有应用可信来源。
- 本次不改代码、Schema、模型端点、凭据、沙箱、权限、门禁和已封存夹具，不启动真实调用，不创建执行/审查新会话。

## 实施顺序与待验证项

先对齐需求/模块接口 → 探测外部应用和主控接续 → 最小 GUI 与单任务闭环 → 模块替换与失败回归 → 产品验收。ZCode 仅为首个候选，其接口、会话寻址、取消和事件能力均待实测。
GUI 技术、自动触发机制与版本化消息协议尚未锁定；不能为本 ADR 编造接口支持或测试结果。长期无人值守恢复另按 N7 规划。
