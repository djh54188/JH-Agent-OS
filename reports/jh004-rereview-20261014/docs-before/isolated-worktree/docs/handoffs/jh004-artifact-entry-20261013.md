## 明确实施项

A. **可信生产装配。** 当前 CLI 在真实模式关闭文件门禁时仍装配 MockToolExecutor，必须改成显式 NoTool/DenyTool 生产执行器。所有模型工具请求都拒绝且不能使任务成功；模型与任务 JSON 不能选工具、扩大权限或选择 fixture。未知 execution_mode 拒绝。不要仅修改名字，检查实际调用与数据库结果。

B. **固定可信任务与验收。** 从现有 records 数据转换选择一个固定模板，预先确定输入结构、排序规则和恰好两项可验证的必需条件；期望结果由可信控制代码从原输入计算。移除本模板对任意 expected_output、sort_by 或验收名的信任，不支持的要求在调用模型前拒绝。保持独立审核绑定当前 task/attempt/产物版本与 SHA-256，模型评分不决定成功。不要在本批扩展任意代码验收器。

C. **来源与接续绑定。** 在可信控制层保存生产/fixture 来源和验收模板标识等不可由模型覆盖的信息；不同 CLI 进程的 resume 沿用原配置、任务额度、截止时间与所有权。fixture 任务不能借切换 CLI 标志被当成真实验收任务，真实任务也不能切换 Mock 完成。避免为此破坏既有协议兼容。未确认调用、未知用量、未知副作用、活跃执行所有者和终态禁止被普通 resume 越过；recover 不作抢占捷径。

D. **只读查询与返回。** status/events/artifact/summary 不建库、不迁移、不调用模型。数据库不存在、任务不存在、尚无产物时返回一致的结构化结果。摘要含命令结果、任务状态、当前产物版本/哈希、审核绑定、必需验收、预算/用量、阻塞与交付范围。成功的查询命令不意味着任务成功；generated_artifact 不意味着 target_applied。

E. **真实项目 Skill。** 在正确工作树落盘最小 Skill 并核验宿主支持的项目技能位置与发现方式；使用现有官方说明/本地能力，不凭名称猜。Skill 只编排已支持 CLI 命令，不自动 approve，不自动 recover，不自动应用目标文件。需实际 Codex 发现/调用，返回当前会话的任务号和产物。旧 C 盘绑定的问题不能靠 Python 的 workdir 参数伪装解决；如宿主确需用户切换项目或重开会话，准确列出最小操作并保留待验证状态。
