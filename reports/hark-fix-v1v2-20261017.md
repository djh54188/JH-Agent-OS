## 2. 根因（统一处理）

旧框架把变异源码 `exec` 到新命名空间：
- V-1：phase4 新建 `types.ModuleType`。
- V-2：jh006 用 `dict(live.__dict__)`。

由此产生两个问题：
1. **类身份分裂**：变异模块重新定义了 `PathBoundaryError` 等异常类，消费者（orchestrator）仍按 live 类捕获。
2. **patch 目标落空**：测试对 `src.xxx.<attr>` 打的 patch 只作用于 live 模块，到不了变异命名空间。

此外：
- phase4 把 errors 计为检出（`failures or errors`），且不跑基线。
- jh006 只有一轮全局对照，没有逐条恒等对照。

修复方式：
- 每条变异的每次运行，都在**一次性仓库副本**的**独立 Python 进程**中执行。变异直接写到副本的源文件上。
- 这样变异模块、全部消费者和测试模块共享同一个导入图：每个异常只有一个类身份，每个 patch 目标只有一个模块属性。
- 原仓库只读（回归测试中有字节比对断言）。
- 两个脚本各内嵌同一份框架代码，以免新增文件超出范围。

## 3. 判定口径（第二版）

每条变异跑三次目标测试，均在一次性副本、独立进程中执行：
1. **基线**：未改副本，必须 pass。
2. **恒等**：锚点替换为自身，走同一写入路径，必须 pass，否则记 `identity_not_green`。
3. **真实变异**：只有带**行为证据**的断言失败才记 `detected`。

### 3.1 R1：检出必须有行为证据（不再读 traceback 文本）

第一版用 traceback 中的失败源码行做正则，无法看到多行断言，也看不出等值断言比较的是文案。第二版改为在子进程中直接读取失败断言的**实时操作数**：

- 子进程包装 `unittest.TestCase` 的断言方法和 `assertRaises*` 的上下文出口。最外层断言失败时，在异常上附加证据，结果对象按每个失败读取。
- **文本**定义：含空白或为空的 str；或者等于/包含某个异常消息的 str。异常消息来自基线运行和本次运行中仓库内代码抛出的异常（`sys.monitoring` RAISE 事件，Python ≥ 3.12）。基线消息会传给恒等和变异两次运行，因此不含空格的错误码文案也能识别。
- 判定规则：
  - 等值族（assertEqual/DictEqual/…/CountEqual）：把操作数中的所有文本替换为同一个不透明记号后重放比较。仍然不等，记 `behavioral`；变为相等，记 `message_only`。
  - assertIn：容器是文本串，或成员是文本，记 `message_only`；集合类容器在不透明化后重放。
  - assertRaises 上下文：期望异常**没有抛出**，记 `behavioral`；抛出了期望类型但正则不匹配，记 `message_only`。
  - assertRegex 类：记 `message_only`。
  - 否定类（NotEqual/NotIn/Is/IsNot）与标量类（True/False/IsNone/比较/IsInstance）：操作数含文本时记 `undetermined`。
  - 若某个非文本操作数（bool/int）的**整段调用表达式**由文本计算而来，记 `undetermined`。调用表达式按指令位置精确定位 AST 节点，多行调用也适用；“由文本计算”包括字符串方法、str()/repr()/len()、re.*、f-string、与字符串常量的 in 比较，以及 message/error_info/reason/exception 等字段。
  - 裸 `assert`、`self.fail`、自定义抛 AssertionError、无法定位的调用、重放出错：记 `undetermined`。
- 结果汇总：任一失败为 `behavioral`，记 `behavioral_failure`，判 detected；全部为 `message_only`，记 `not_detected_message_only_failure`；其余记 `not_detected_undetermined_failure`。**无法确定时不计检出。**
- 没有证据的失败（只有 traceback 文本），一律记 undetermined。旧的 `_failing_source_line` 及正则已全部删除。

### 3.2 R2：平台阻塞必须有明确平台前提证据

- 基线不绿时，**只有**满足以下条件之一才记 `platform_blocked`：
  - skip 原因明确写出所需平台（如 “requires Windows …”、“windows-only”），且与当前主机平台不同；
  - error 的最终异常是导入仅存在于另一平台的模块（`_winapi`、`winreg`、`msvcrt` 等；在 Windows 上对应 `fcntl`、`pwd` 等），或启动仅存在于 Windows 的可执行文件（`cmd`、`mklink`、`powershell`），且当前主机不是该平台。
- 其他所有红基线都记 `baseline_not_green` 并判失败。包括：普通断言失败、其他 error、加载失败、含糊的 skip 原因（如 “platform”）、测试数不为 1。
- 超时及子进程无结果，记 `harness_error`，判失败。

### 3.3 退出码

- 0：全部 detected。
- 2：每行都是 detected 或 platform_blocked，且至少一行 platform_blocked。
- 1：其余所有情况。

## 7. 局限与未验证

- **Windows 未验证**：phase4 的 3 条 platform_blocked、1 条 baseline_not_green，以及 Windows 下的整体退出码。
- **Windows 默认临时目录限制**：
  - 一次性副本默认放在 `tempfile.gettempdir()` 下，Windows 上通常是 `%TEMP%`（`C:\Users\<用户>\AppData\Local\Temp`）。
  - 该路径可能包含 8.3 短名，也可能触及 MAX_PATH 长度限制。对依赖 realpath、junction 或 reparse 判断的 phase4 测试，这可能改变基线结果。
  - 本版新增环境变量 `JH_MUTATION_TMP`，可把副本放到指定目录，报告 JSON 的 `tmp_root` 会记录实际位置。但默认目录与该变量在 Windows 上的效果都**未验证**。
- **溯源依赖 `sys.monitoring`**（Python ≥ 3.12）。若不可用，只按“含空白或为空”识别文本；每行 JSON 的 `provenance` 字段记录是否启用。
- **证据规则偏保守**：可能把真实的行为变化记为 undetermined。这只会少计检出，不会多计。
- **耗时**：Linux 上 phase4 约 11 秒、jh006 约 23 秒、回归测试约 70 秒（单机，无并发）。

### 9.1 问题 1：标量操作数的纯文案误报

- 复现：合成夹具把 `test_bool_from_text` 改为 `good = result["error_info"].endswith("over limit")`，再 `self.assertTrue(good)`，异常消息由 value over limit 改为 value too high。13bb17d 的两个脚本均报 detected（behavioral/non-text operands）、exit 0。原因：只在断言调用的实参表达式里找文本派生，局部变量把派生过程藏住了。
- 修复：bool/int/float/None 操作数自身不带文本，不透明重放看不出测试侧把文案算成了布尔值。现在任何含标量的操作数必须**证明来源**才可能记 behavioral，否则一律 undetermined。证明是局部、保守的，不是通用数据流分析：
  - 非字符串常量；模块级 int/float/None；
  - 调用：被调者为纯名字/属性链，在帧内解析后定义在 `<root>/src` 下，或为类构造器，或 Path 的 exists/is_file/is_dir/is_symlink；
  - 属性/下标读取（常量或名字键），其根为 self、with-as 名，或由一次简单赋值绑定到已证明的调用/读取；测试自建的字面量（如 dict）不算；
  - 函数内**恰好一次**简单赋值、且在断言之前绑定的局部名，递归证明其右值；
  - not/and/or/比较/算术，需各部分均已证明。
  - 不予证明：tests 下的辅助函数、str 方法、len/bool/any 等内建、re、元组解包、循环变量、参数、多次赋值。
- 新增反例（均 MSG→MSG_CHANGED，期望 undetermined、不计检出）：局部变量、内联、辅助函数返回值、辅助函数返回值存局部、int 计数存局部、多级局部链、测试自建 dict、同名局部重绑定。新增正例（期望 detected）：`assertFalse(consumer.allowed(11))` 与其局部变量写法。
- 13bb17d 对 6 个新反例全部判 detected、exit 0（`raw-r3/prefix_counterexamples_13bb17d.json`）。
