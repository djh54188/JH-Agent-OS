## 产品边界

- Codex 是主要交互入口与基础执行环境。
- 优先复用 Codex 的 Coding、文件、Shell、Git、项目上下文、基础记忆和工具调用。
- JH 负责跨供应商模型接入、协作协议、任务预算、审核与产物关联、修复控制及项目级状态。
- 工具边界按 [ADR-0003](docs/adr/ADR-0003-codex-hosted-entry.md)与 [ADR-0004](docs/adr/ADR-0004-n1-artifact-first.md)执行：取消自研通用 Shell/Git 平台；自动应用组件保留为未通过的暂停工作，真实写入门禁关闭。当前 N1 接入只生成并保存审核产物，不应用到用户目标文件。
- 当前 MVP 聚焦多模型协作闭环。独立 UI、完整自主 Runtime、全天候云端运行和系统级自我修改暂缓。

项目级 Skill + 结构化 CLI 的最小接入方向已批准，实际 Codex 内接入尚未验收；是否需要 MCP 由后续接入验证决定。文档中的工作流程约定不等于已经实现了工具权限强制执行。

## 开发入口

在项目根目录执行：

    python -m src.cli --help
    python -m unittest discover -s tests

第一条查看现有开发 CLI；它的存在不代表 Codex 内产品入口已经验收。第二条是离线测试入口；本轮文档整理未重新运行测试。

Gemini 接入见 [gemini-setup.md](docs/gemini-setup.md) 和 [ADR-0002](docs/adr/ADR-0002-gemini-local-proxy.md)。
Muse 接入见 [muse-setup.md](docs/muse-setup.md)。
凭据通过环境变量或既有密钥机制提供，不写入这些文档。

真实模型取证脚本会消耗模型资源，并可能刷新报告；按本批验收需要运行，不能作为无意义的常规重跑。

## 方向变化后的主动对齐

用户于 2026-10-12 明确要求：此类关联事项由架构师主动处理，不等待用户逐项提醒。

当产品方向、需求、阶段划分、角色分工或验收口径改变时，架构师应在本次交付中完成：

1. 检查对现有实现、正在执行的批次、审查范围、接入 ADR 和历史验收的影响。
2. 按实际影响同步产品需求、路线、状态、任务与变更记录，保留旧证据，区分规划、实现、验证、审查和结项。
3. 主动检查执行 AI 与审查 AI 是否都需要对齐；仅为需要采取行动的一方生成可直接转发的交接，引用同一需求与路线基线，不等用户提醒，空栏目不输出。
4. 核对阶段编号、角色职责、文档引用及验收条件，明确本批范围和暂缓事项，避免两方按不同目标工作。
5. 尊重正在执行的工作，安排安全交接节点，不用方向调整覆盖未完成源码。
6. 常规对齐自主完成；确需外部输入或重大裁决时，单列问题、影响、选项和推荐，不制造额外审批。

续接会话先读 STATUS.md；需求或路线变化时重读相关基线，再生成交接。

## 协作交接

研发协作按用户 2026-10-12 最新分工：当前架构师会话兼任最终研发审查，负责规划、架构决策、代码与证据复核及阶段结项；Muse 主执行与整合，Gemini 承担多个范围明确的执行子任务。执行方直接将交付包发回本会话，由本会话完成审查与裁决。当前推进 [JH-004 真实生成产物接入](docs/handoffs/jh004-artifact-entry-20261013.md)；JH-015 发布设计暂停且未通过，JH-016 本轮矩阵复核为 STOP，保留证据和真实写入门禁。执行报告区分已验证事实、推测和未验证事项。

完整主执行提示词见 [Muse 主执行与 Gemini 子智能体交接](docs/handoffs/muse-lead-gemini-workers.md)。该分工适用于项目研发协作，产品运行时 Worker/Reviewer 与接入配置仍按现有 ADR；参与实现者的自检不充当独立审查。

用户于 2026-10-12 明确：执行 AI 以实现、修复和举证为主要职责。其架构建议只作为候选输入；架构师应独立核对需求、代码与证据后裁决，不直接照收执行方的推荐、完成声明或测试全绿结论。普通实现选择仍由执行方自主处理。

执行方直接交付实现与证据给当前架构师兼审查会话，确有架构裁决项时单独列出。本会话合并输出审查结论与架构裁决，仅在需要执行方整改或用户提供输入时生成对应内容，不再生成发给自己的架构师交接。具体审查要求见[审查任务说明](docs/handoffs/n1-20261012-review.md)。
用户于 2026-10-12 明确：没有新增问题、新阻塞、需处理的状态变化或待裁决事项时，不生成转发内容，不重复旧结论或已批准事项；平台需要完成反馈时仅写“无新增事项，无需转发”。审查证据仍保留，已有未关闭问题不因此视为通过。

旧工程阶段采用 E1—E8，新开发阶段采用 N1—N8，产品分组采用 P1—P4。三者含义见 ROADMAP.md，历史结项不改名套用。
