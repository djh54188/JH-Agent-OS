# JH-Agent OS

基于 Codex 的个人 AI Agent 增强系统。用户在 Codex 中提出目标，JH 补充跨模型协作、任务控制、独立审核和长期项目管理能力。

项目目录：D:/JH-Agent OS。产品需求来自用户 2026-10-11 提供的 v1.0；当前状态与验收范围见 [STATUS.md](STATUS.md)。

## 产品边界

- Codex 是主要交互入口与基础执行环境。
- 优先复用 Codex 的 Coding、文件、Shell、Git、项目上下文、基础记忆和工具调用。
- JH 负责跨供应商模型接入、协作协议、任务预算、审核与产物关联、修复控制及项目级状态。
- 工具的具体职责与权限边界在新阶段 N1 验证；现有文件工具是否保留，以必要性和独立审查为依据。
- 当前 MVP 聚焦多模型协作闭环。独立 UI、完整自主 Runtime、全天候云端运行和系统级自我修改暂缓。

Skill + 现有 CLI 是待验证的最小接入候选；是否需要 MCP 由接入验证决定。文档中的工作流程约定不等于已经实现了工具权限强制执行。

## 开发入口

在项目根目录执行：

    python -m src.cli --help
    python -m unittest discover -s tests

第一条查看现有开发 CLI；它的存在不代表 Codex 内产品入口已经验收。第二条是离线测试入口；本轮文档整理未重新运行测试。

Gemini 接入见 [gemini-setup.md](docs/gemini-setup.md) 和 [ADR-0002](docs/adr/ADR-0002-gemini-local-proxy.md)。
Muse 接入见 [muse-setup.md](docs/muse-setup.md)。
凭据通过环境变量或既有密钥机制提供，不写入这些文档。

真实模型取证脚本会消耗模型资源，并可能刷新报告；按本批验收需要运行，不能作为无意义的常规重跑。

## 方向变化后的主动对齐

用户于 2026-10-12 明确要求：此类关联事项由架构师主动处理，不等待用户逐项提醒。

当产品方向、需求、阶段划分、角色分工或验收口径改变时，架构师应在本次交付中完成：

1. 检查对现有实现、正在执行的批次、审查范围、接入 ADR 和历史验收的影响。
2. 按实际影响同步产品需求、路线、状态、任务与变更记录，保留旧证据，区分规划、实现、验证、审查和结项。
3. 同时给出可直接转发给执行 AI 与审查 AI 的两份交接文字，引用同一需求与路线基线，不等用户再问另一方是否需要对齐。
4. 核对阶段编号、角色职责、文档引用及验收条件，明确本批范围和暂缓事项，避免两方按不同目标工作。
5. 尊重正在执行的工作，安排安全交接节点，不用方向调整覆盖未完成源码。
6. 常规对齐自主完成；确需外部输入或重大裁决时，单列问题、影响、选项和推荐，不制造额外审批。

续接会话先读 STATUS.md；需求或路线变化时重读相关基线，再生成交接。

## 协作交接

执行方先交独立审查，再申请架构师阶段结项。执行报告区分已验证事实、推测和未验证事项。

执行方输出“给审查 AI”的交付与证据，以及单独的“给架构师”的裁决项。
审查方输出“给执行 AI”的整改，以及单独的“给架构师”的结论和裁决项。
无裁决项时写“无需架构师裁决”，不用制造审批事项。

旧工程阶段采用 E1—E8，新开发阶段采用 N1—N8，产品分组采用 P1—P4。三者含义见 ROADMAP.md，历史结项不改名套用。
